## C02 store-persistence slice

Main freezes `SubtaskStore.checkpoint()`, `SubtaskStore.restore(data,{parents,sourceCurrent})` and exported `subtaskCheckpointIsValid(data)` in `src/core/subtasks.ts`. Store payload has internal version1, group/child allocators and bounded groups/provenance/report receipts/replay proof; it is a component of planned strict v11, **not** a new active session format. Active hybrid checkpoint remains v10 until C05. Store checkpoint rejects unsupported/corrupt shapes, bounds, statuses/IDs/duplicate ownership or allocator regression without migration/repair. It returns detached canonical plain data; full serialized store<=65536bytes, throwing rather than evicting facts on overflow. Preserve C01 no-getter/toJSON/custom-prototype/hidden-key invariants and bounded traversal.

Persist latest admission replay as a content-free digest, not raw serialized proposal/request text. Exact replay after reload preserves reports/IDs. Retain canonical report provenance for active and retired children, including explicit retractions, plus list/proposal/removal sources; status must not survive without supporting report receipt. A stale list/child/retirement source drops only its affected group; a stale report source resets only affected reported status to pending. Parent absence/requirements revision mismatch drops its group, archival retains sidecar but prevents updates; same-revision parent wording edits do not erase immutable admission provenance. Always preserve allocator high-water despite stale group pruning. Restore rebuilds complete current parent authority from supplied parents, including those without groups; never trust persisted parent availability. `sourceCurrent(SourceRef)` is synchronous canonical validation; false/throw means stale, not permission. Returned store/payload/snapshots are detached. No workbook inventory/access receipts or tool precondition.

Main `subtasks-checkpoint.test.ts` freezes this slice. C02 is not accepted until durable gate/proposal journals, optional/full strict-v11 envelope bounds and write-failure atomicity are covered and independently reviewed. No runtime/v10 cutover, phase/provider wiring, paid calls or deletion of historical regression coverage in this first slice.

## Pure reducer (`SubtaskStore`)

`admit(input)`, `report(input)`, `reconcile(parents)`, `snapshot()` and later `checkpoint()/restore()` are local only. Source/model/currentness validation belongs upstream; reducer still validates exact structure, immutable source-reference shape, hashes, non-empty control-free labels, ownership, revisions and bounds. [ref:coverage_not_task_authority]

Admission shape:

```ts
interface SubtaskAdmission {
  parent: HybridTask;
  expectedListRevision: number; // 0 for first admission; compare-and-swap thereafter
  source: SourceRef; // canonical grounds for this mutation, not a tool receipt
  proof: { contextHash: string; gateRequestHash: string; proposalRequestHash: string };
  children: Array<
    | { kind: "add"; label: string; source: SourceRef }
    | { kind: "retain"; id: string }
    | { kind: "reword"; id: string; label: string; source: SourceRef }
    | { kind: "replace"; id: string; label: string; source: SourceRef }
  >;
  removals: Array<{ id: string; source: SourceRef; reason: "withdrawn" | "out-of-scope" }>;
  complete: boolean; // evidence-backed exhaustive set only, not merely a full JSON array
  knownTotal?: number;
}
```

Returns `{accepted:true}` or `{accepted:false, reason:"invalid"|"capacity"|"stale"|"foreign"}`. Every previous active child occurs exactly once among retained/reworded/replaced/removal references. New list order is children order. Explicit replacement retires old ID and creates new pending ID. Retired identities count toward session retained capacity. Unknown references, duplicate use, unsupported keys/raw payloads or inconsistent totals reject whole input without allocating IDs or mutating prior state. Source refs are the existing canonical role/entry/hash/range/quote-hash type; nonempty exact ranges required.

Reason taxonomy: malformed schema/hash/source, empty or control-bearing labels, duplicate use, silent omissions and inconsistent totals are `invalid`; unknown or other-group child references are `foreign`; obsolete list/parent bindings and archived mutation attempts are `stale`; group/child/scalar/byte bounds are `capacity`. Reject before state or allocator mutation. A mixed local/foreign report cannot advance its local prefix.

One group per parent requirements revision. Group snapshot: `id,parentTaskId,parentRevision,parentSourceDigest,listRevision,source,proof,complete,knownTotal?,children,retired,omissions`. Active child: `id,label,status,source`; status is pending/reported-completed/reported-blocked. Retired child retains its old fields plus `retirement:{source,reason}`; replacement reason is `replaced`. Tool access is optional external evidence, not an initial generic reducer requirement. No mandatory resourceKey, callId or inventory source. Group/child IDs are code-owned opaque `subtask-group:<n>`/`subtask-child:<n>` with monotonic allocators starting at1. `parentSourceDigest` is SHA-256 of UTF-8 JSON `[entryId,messageHash,role,start,end,quoteHash]` in that order. `omissions` is a detached string array describing non-exhaustive scope and retained removals; wording is not API identity. Admission source/proof and child/retired provenance are detached immutable copies, not only request-local validation inputs.

Initial admitted list revision is1. Structural/reword/refinement transactions increment list revision; retain-only identical state is no-op. Exact successful input replay is idempotent even though its expected prior revision is now old, but only against the same current parent revision and latest admitted transaction identity; do not replay stale older transactions across intervening changes. New proofs/context without an actual list change can be recorded by the phase journal, not fabricate new child work or recursively trigger a gate. New groups may be empty for attributed count-only scope with an explicit `knownTotal`; first admission with no children and no total is `invalid` and creates no sidecar (an empty LLM proposal is an upstream no-op). First admission cannot remove any prior child: any removal reference is `foreign`, including a real child of another parent. Parent inclusion/revision still required.

Default generated decomposition is `complete:false`, absent knownTotal; current tracked count is children.length. A complete set requires knownTotal absent or equal to current active count; an incomplete knownTotal cannot be less than active count. Count-only total does not invent labels. Capacity:64 active/group;200 retained children/session (active+retired);200 retained groups including empty;240 Unicode scalars/label;32KiB admission projection and64KiB whole optional checkpoint. Admission bytes mean UTF-8 JSON of the entire validated detached field projection including parent, sources, proof and operation fields; for ordinary inert input this equals `Buffer.byteLength(JSON.stringify(input), "utf8")`. Reject unsupported own keys (including hidden keys) and custom prototypes; never invoke caller serialization hooks for size or replay identity. Exactly32768 fits,32769 rejects. Preflight operation arrays at64 entries before reading elements; reports require dense arrays of1–64 IDs. Oversized operation arrays are `capacity`, malformed/oversized reports are `invalid`. Bound scalar scanning rather than materializing unbounded input. Unicode label limits count scalar values, not UTF-16 code units or UTF-8 bytes:240 astral characters fit,241 reject. No silent retirement eviction.

Report shape: `{groupId,listRevision,childIds,source,status}`. Only current active child IDs; nonempty unique child batch, matching current list, included parent, valid source/status. Whole batch rejects on foreign/stale input. Explicit retraction uses pending. Reports never edit list identity/order or parent state. Access alone cannot call report. Snapshots and input references never alias internal state.

A successful `reconcile(parents)` is authoritative for parent presence, revision and inclusion even before any group exists. Removed/archived or older-revision admissions are stale; retained group absence must not revive delayed work. Reports to previously allocated invalidated group IDs are stale; never-allocated group IDs are foreign. Parent requirements revision invalidates old group; source/label wording changes without requirements revision preserve child identity/status and original group provenance. Archive retains facts, disables further mutations/reports; reinclusion permits later current-authority work. Parent DONE never auto-completes/reopens children or gets reopened by them.

## Jev gate / selected-model protocol (C03a/C03)

Gate input: bounded immutable current eligible parent bindings, complete required existing-child snapshots, newest and bounded preceding whole canonical observations, omission markers, optional validated names-only evidence. Current parent source must be included. Split parent batches to respect24KiB/20questions; a parent whose required context cannot fit is unavailable, not sampled. Context identity includes all actual inputs/version/bindings, excluding UI focus/health/cost scalars. Accepted yes requires confidence>=0.5, selected probability>=0.8 at jev-1.13.0; no/uncertain/unavailable produces no LLM call. Receipt scopes yes to exact parent/current child revision/context. No parent-source mutation or task completion authority.

LLM response strict JSON `{proposals:[...]}`; one proposal per supplied yes-parent index, max20. Proposal has `{parentIndex,children,removals,complete,knownTotal?}`. New child `{kind:"add",label,evidence:[{contextIndex,start,end}]}`; existing forms retain/reword/replace use `childIndex` into supplied current children instead of durable id; reword/replace carry label/evidence. Removal uses `{childIndex,reason,evidence}`. All supporting ranges reference supplied canonical user/assistant/intercom text; labels may paraphrase/imply meaningful steps. `complete:true` requires full-set grounds, not inference that model covered everything. Canonical ref mapping and request proof construction are code-owned. Output may be `{proposals:[]}`; no mutation. No raw IDs/revisions/resource hashes/status assignments accepted from model.

Validate response <=32KiB and selected-model transport existing2048 output-token cap; oversized/truncated response rejects atomically. No pagination/automatic retry to force64 long labels into a response. Capacity is an upper bound, not a guarantee every maximal proposal fits. Supporting exact text establishes provenance, not a proof of semantic usefulness. Frozen quality gate checks that separate concern.
