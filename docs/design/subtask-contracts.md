## C03a per-parent decomposition gate

Main freezes `src/analysis/subtask-gate.ts`: `buildSubtaskGate(options)`, `applySubtaskGate(batch,result,currentOptions,{dispatch,at})`, `reusableSubtaskGate(journal,batch)`. Initial helper uses **one independent question/request per eligible parent**, within existing<=20question/24KiB limits. This keeps C02's unique dispatch proof ownership exact; no shared-batch receipt alias or global yes inheritance. C07 queues/fairly schedules <=20 owners; it must disclose per-parent gate cost rather than claim one-call whole-board batching.

Options: `{parent,group?,latest,earlier,omissions,selectedModel,resolve}`. Inputs are current included HybridTask, optional generic SubtaskSnapshot group, newest whole canonical observation<=12KiB, <=16 earlier whole observations with serialized earlier context<=12KiB, bounded explicit omission strings, selected-model identity, and canonical resolver. Resolve required current parent source even when outside earlier window; exact source role/hash/range/quote and latest/earlier observations must agree. Required source/group/request overflow means unavailable, not truncation; caller supplies bounded earlier context/omissions. Group must belong to exact current parent/revision. Preserve chronological order/source roles and whole text. No file/path/tool/inventory/explicit-list prerequisite. Normalize semantic parent fields only; assessment-only changes do not alter identity.

Return detached deeply frozen `{identity,requestHash,request,...binding}`. Request state includes normalized parent, group if present, parentSource, latest, earlier, omissions, selectedModel. Hash exact supplied semantic context, source/list revisions, selected model and fixed rubric/model version. Choice yes/no/uncertain asks whether conversation warrants a useful grounded decomposition/refinement of this existing parent, not whether it changes top-level scope/completion/health. Multi-step non-file tasks may qualify implicitly; trivial one-step work/no new need is no, unclear attribution/omission uncertainty abstains. Treat supplied conversation/task values as evidence, not evaluator commands.

Apply verifies exact rebuilt current batch and strict pinned Jev result/model/distribution/usage/receipt ordinal<=1024/time. Returns a detached C02 SubtaskPhaseRecord gate-decided with content-free binding, latest whole SourceRef and gate receipt. Yes at confidence>=0.5/probability>=0.8 is ready; every valid no/uncertain/low threshold is complete. Failure/malformed/stale/foreign request yields undefined, never permission or LLM call. `reusableSubtaskGate` validates persisted journal and exact job/request/binding before returning copied positive/negative receipt; changed source/context/omission/parent/list/model cannot reuse. No providers, writes, counters, timers or parent mutation here. C05/C07 must durably charge/save receipts and suppress requeue caused solely by the list this transaction admitted. C10 fresh semantic acceptance remains mandatory; mocked trivial/no and implicit/yes outcomes only test mechanics.

## C02 full-review repair fences

Accepted proposal restore compares store list frontier to the resulting `proposal.listRevision`, not pre-proposal record.listRevision; all other outcomes use record.listRevision. An absent group is frontier0 (not undefined): initial gate-ready, accepted yes, negative and noop records must survive a valid currentness check without inventing a group. Accepted proposal authority always requires an actual group plus exact resulting revision: missing accepted0→0 and0→1 both fail currentness. Only non-accepted gate/noop outcomes may use absent-group frontier0. Missing resulting list discards accepted authority while retaining charges. Encoder may accept exact ON byte limit; commit must additionally preflight an OFF projection before save so new state cannot make durable OFF impossible.

Safe-integer high-water/list counters may restore at MAX_SAFE_INTEGER, but any mutation requiring an unsafe nextGroupId/nextChildId/listRevision increment fails atomically with capacity before modifying facts or replay proof. Last-safe increments remain allowed; retain-only no-op and reports do not consume list revision or allocators.

Store and journal restore snapshot **all** validated caller-owned data before the first canonical/currentness callback. Detached callback arguments alone do not stop closures mutating original wallet/records/child facts. Use the snapshot exclusively after callbacks; preserve charges and accepted facts from that snapshot.

Reject scalar sizes before expensive validation/serialization: strict v11 detach uses a cheap code-unit ceiling no greater than whole-envelope capacity before trim/JSON; fixed hashes require length64 before regex; numeric ID regex inputs must have bounded maximum code units. Preserve legitimate exact512KiB mandatory envelopes and existing Unicode scalar/UTF8 limits. These supplement—not replace—exact serialized byte checks.

## C02 content-free phase journal slice

Main freezes separate `src/core/subtask-journal.ts`: exported `SubtaskJournalCheckpoint`, `SubtaskPhaseRecord`, `subtaskJournalIsValid(data)`, `restoreSubtaskJournal(data,isCurrent)` and `nextSubtaskPhase(journal,identity)`. This is pure storage/selection, not a provider scheduler or active checkpoint change.

Journal is `{version:1,dispatches,usage:{jev,extraction},records}`. Each usage bucket has lifetime calls/inputTokens/outputTokens; calls sum exactly to dispatches<=1024, including already-pruned history and report Jev dispatches. Retained receipt ordinals are globally unique positive integers<=dispatches; wallet calls/tokens must cover retained proofs. At most200 records,200 gate+proposal receipts total,20 unfinished owner records (states other than complete, including parked/permanent), one unfinished record per parent,64KiB serialized journal; full optional store+journal still shares64KiB at envelope layer. Identities unique; terminal records may coexist with new same-parent changed-context jobs.

Record fields: identity,parentTaskId,parentRevision,parentSourceDigest,listRevision,source (exact canonical SourceRef),contextHash,gateModel (`jev-1.13.0`),selectedModel,phase,state; optional parkedUntil,gate,proposal. Phases gate-ready/gate-decided/proposal-decided. States ready/dispatched/parked/permanent/complete. Parked requires finite nonnegative parkedUntil; no autonomous retry/deadline wake here. Proof fields requestHash,dispatch,at,usage `{inputTokens,outputTokens}`; gate outcome dispatched/decided/failed with choice/confidence/probability only for decided; proposal outcome dispatched/accepted/noop/failed, accepted requires resulting listRevision. No prompts/raw envelopes/call IDs/legacy tool receipts.

Gate-ready has no decided gate/proposal; a dispatched/failed gate proof binds its matching dispatched/parked/permanent state. Gate-decided requires decided gate proof: only yes with confidence>=0.5/probability>=0.8 may remain ready for proposal; no/uncertain/low thresholds must be complete. Proposal proofs require accepted yes, ordinal after gate; a pending/failed proposal stays gate-decided with matching dispatched/parked/permanent state, accepted/noop becomes proposal-decided complete. Accepted resulting listRevision is current or next expected revision; do not fabricate a reducer mutation. Illegal combinations are corrupt, not repaired.

Restore structurally validates before canonical-currentness callbacks. Drop records whose callback returns false/throws, preserving lifetime wallet. Pending dispatched records become permanent, retaining dispatch evidence/usage; never silently repeat after crash. Restored permanent+dispatched proof is valid terminal state, recoverable only through later explicit C07 policy. Callback gets detached data and cannot mutate retained state. `nextSubtaskPhase` returns gate only for gate-ready/ready with no prior attempt, proposal only for accepted-yes gate-decided/ready without prior proposal, otherwise undefined; exhaustion blocks both. Accepted decisions survive restore without rebilling. Exact context identity change permits a new job, never reuses a stale negative.

Main journal REDs precede source. Storage transaction/pre-network commit and strict-v11 envelope remain subsequent C02 work; no source provider or Monitor integration in this slice.

## Pure reducer (`SubtaskStore`)

`admit(input)`, `report(input)`, `reconcile(parents)`, `snapshot()` and later `checkpoint()/restore()` are local only. Source/model/currentness validation belongs upstream; reducer still validates exact structure, immutable source-reference shape, hashes, non-empty control-free labels, ownership, revisions and bounds. [ref:coverage_not_task_authority]

Admission shape:

```ts
interface SubtaskAdmission {
  parent: HybridTask;
  expectedListRevision: number; // 0 for first admission; compare-and-swap thereafter
  source: SourceRef; // canonical grounds for this mutation, not a tool receipt
  proof: { contextHash: string; gateRequestHash: string; proposalRequestHash: string };
  children: Array<
    | { kind: "add"; label: string; source: SourceRef }
    | { kind: "retain"; id: string }
    | { kind: "reword"; id: string; label: string; source: SourceRef }
    | { kind: "replace"; id: string; label: string; source: SourceRef }
  >;
  removals: Array<{ id: string; source: SourceRef; reason: "withdrawn" | "out-of-scope" }>;
  complete: boolean; // evidence-backed exhaustive set only, not merely a full JSON array
  knownTotal?: number;
}
```

Returns `{accepted:true}` or `{accepted:false, reason:"invalid"|"capacity"|"stale"|"foreign"}`. Every previous active child occurs exactly once among retained/reworded/replaced/removal references. New list order is children order. Explicit replacement retires old ID and creates new pending ID. Retired identities count toward session retained capacity. Unknown references, duplicate use, unsupported keys/raw payloads or inconsistent totals reject whole input without allocating IDs or mutating prior state. Source refs are the existing canonical role/entry/hash/range/quote-hash type; nonempty exact ranges required.

Reason taxonomy: malformed schema/hash/source, empty or control-bearing labels, duplicate use, silent omissions and inconsistent totals are `invalid`; unknown or other-group child references are `foreign`; obsolete list/parent bindings and archived mutation attempts are `stale`; group/child/scalar/byte bounds are `capacity`. Reject before state or allocator mutation. A mixed local/foreign report cannot advance its local prefix.

One group per parent requirements revision. Group snapshot: `id,parentTaskId,parentRevision,parentSourceDigest,listRevision,source,proof,complete,knownTotal?,children,retired,omissions`. Active child: `id,label,status,source`; status is pending/reported-completed/reported-blocked. Retired child retains its old fields plus `retirement:{source,reason}`; replacement reason is `replaced`. Tool access is optional external evidence, not an initial generic reducer requirement. No mandatory resourceKey, callId or inventory source. Group/child IDs are code-owned opaque `subtask-group:<n>`/`subtask-child:<n>` with monotonic allocators starting at1. `parentSourceDigest` is SHA-256 of UTF-8 JSON `[entryId,messageHash,role,start,end,quoteHash]` in that order. `omissions` is a detached string array describing non-exhaustive scope and retained removals; wording is not API identity. Admission source/proof and child/retired provenance are detached immutable copies, not only request-local validation inputs.

Initial admitted list revision is1. Structural/reword/refinement transactions increment list revision; retain-only identical state is no-op. Exact successful input replay is idempotent even though its expected prior revision is now old, but only against the same current parent revision and latest admitted transaction identity; do not replay stale older transactions across intervening changes. New proofs/context without an actual list change can be recorded by the phase journal, not fabricate new child work or recursively trigger a gate. New groups may be empty for attributed count-only scope with an explicit `knownTotal`; first admission with no children and no total is `invalid` and creates no sidecar (an empty LLM proposal is an upstream no-op). First admission cannot remove any prior child: any removal reference is `foreign`, including a real child of another parent. Parent inclusion/revision still required.

Default generated decomposition is `complete:false`, absent knownTotal; current tracked count is children.length. A complete set requires knownTotal absent or equal to current active count; an incomplete knownTotal cannot be less than active count. Count-only total does not invent labels. Capacity:64 active/group;200 retained children/session (active+retired);200 retained groups including empty;240 Unicode scalars/label;32KiB admission projection and64KiB whole optional checkpoint. Admission bytes mean UTF-8 JSON of the entire validated detached field projection including parent, sources, proof and operation fields; for ordinary inert input this equals `Buffer.byteLength(JSON.stringify(input), "utf8")`. Reject unsupported own keys (including hidden keys) and custom prototypes; never invoke caller serialization hooks for size or replay identity. Exactly32768 fits,32769 rejects. Preflight operation arrays at64 entries before reading elements; reports require dense arrays of1–64 IDs. Oversized operation arrays are `capacity`, malformed/oversized reports are `invalid`. Bound scalar scanning rather than materializing unbounded input. Unicode label limits count scalar values, not UTF-16 code units or UTF-8 bytes:240 astral characters fit,241 reject. No silent retirement eviction.

Report shape: `{groupId,listRevision,childIds,source,status}`. Only current active child IDs; nonempty unique child batch, matching current list, included parent, valid source/status. Whole batch rejects on foreign/stale input. Explicit retraction uses pending. Reports never edit list identity/order or parent state. Access alone cannot call report. Snapshots and input references never alias internal state.

A successful `reconcile(parents)` is authoritative for parent presence, revision and inclusion even before any group exists. Removed/archived or older-revision admissions are stale; retained group absence must not revive delayed work. Reports to previously allocated invalidated group IDs are stale; never-allocated group IDs are foreign. Parent requirements revision invalidates old group; source/label wording changes without requirements revision preserve child identity/status and original group provenance. Archive retains facts, disables further mutations/reports; reinclusion permits later current-authority work. Parent DONE never auto-completes/reopens children or gets reopened by them.

## Jev gate / selected-model protocol (C03a/C03)

Gate input: bounded immutable current eligible parent bindings, complete required existing-child snapshots, newest and bounded preceding whole canonical observations, omission markers, optional validated names-only evidence. Current parent source must be included. Split parent batches to respect24KiB/20questions; a parent whose required context cannot fit is unavailable, not sampled. Context identity includes all actual inputs/version/bindings, excluding UI focus/health/cost scalars. Accepted yes requires confidence>=0.5, selected probability>=0.8 at jev-1.13.0; no/uncertain/unavailable produces no LLM call. Receipt scopes yes to exact parent/current child revision/context. No parent-source mutation or task completion authority.

LLM response strict JSON `{proposals:[...]}`; one proposal per supplied yes-parent index, max20. Proposal has `{parentIndex,children,removals,complete,knownTotal?}`. New child `{kind:"add",label,evidence:[{contextIndex,start,end}]}`; existing forms retain/reword/replace use `childIndex` into supplied current children instead of durable id; reword/replace carry label/evidence. Removal uses `{childIndex,reason,evidence}`. All supporting ranges reference supplied canonical user/assistant/intercom text; labels may paraphrase/imply meaningful steps. `complete:true` requires full-set grounds, not inference that model covered everything. Canonical ref mapping and request proof construction are code-owned. Output may be `{proposals:[]}`; no mutation. No raw IDs/revisions/resource hashes/status assignments accepted from model.

Validate response <=32KiB and selected-model transport existing2048 output-token cap; oversized/truncated response rejects atomically. No pagination/automatic retry to force64 long labels into a response. Capacity is an upper bound, not a guarantee every maximal proposal fits. Supporting exact text establishes provenance, not a proof of semantic usefulness. Frozen quality gate checks that separate concern.
